# OpenCode free provider (`opencode`) — four gap fixes

Scope: **only** the keyless free `opencode` provider lane. `opencode-zen` and
`opencode-go` are out of scope (touched only where a shared helper changes
behaviour for them, which is called out explicitly).

Reference: [azrinaldi/opencode-free-bridge](https://github.com/azrinaldi/opencode-free-bridge)
v2.3.1. This is **not** an upstream-parity port — that repo is a single-provider
Node/Bun shim, not our upstream (`decolua/9router`). Where its findings disagree
with our architecture, ours wins; see AGENTS.md §1.

---

## Background: what the reference project found

All four items below come from measured findings in that repo, each verified
against our code. None are style preferences.

---

## 1. Do not retry an IP-abuse refusal (`internal/proxy/executor/opencode_retry.go`)

**Problem.** Upstream returns the *same* `403` + `FreeTierError` body for at
least five unrelated causes:

| Cause | Recoverable? |
|---|---|
| egress IP refused/throttled | no — terminal |
| egress IP flagged for *abusive traffic* | no — terminal, and **retrying extends the penalty** |
| declared tools are not the CLI built-ins | no — the body is already shaped |
| User-Agent not the CLI shape | no |
| missing session header | no |

Our `isOpenCodeRefusal` (`opencode_retry.go:43`) is status + `FreeTierError`
token only, so all five look identical. Every request from a blocked IP
therefore burns a guaranteed-useless second upstream call plus the 200 ms sleep,
and repeating it prolongs the block.

**Changes** (signature of `forwardOpenCode` stays put — no call-site churn in
`providers.go` / `opencode_zen.go`):

1. Add a narrow, case-insensitive terminal classifier next to `isOpenCodeRefusal`:

   ```go
   var openCodeAbusePhrases = []string{
       "detected abusive traffic", "abuse traffic", "abuse of traffic",
   }
   func isOpenCodeTerminalRefusal(ue *proxy.UpstreamError) bool
   ```

   Use an ASCII case-fold `[]byte` scan — **not** `bytes.ToLower`: the body is
   capped at `constants.UpstreamErrLimit` (1 MiB), and lowercasing a MiB on a
   1 vCPU box is a real cost (§4.G).

   **Do not** copy the width of `fallback.go:425`, which matches bare `"abuse"`.
   That would classify any body mentioning "anti-abuse" as terminal and discard
   a legitimate retry.

2. Short-circuit in `forwardOpenCode` — after the `isOpenCodeRefusal` gate
   (`:103`), **before** the `StrictProxy` check (`:107`) and before the sleep
   (`:111`): return the refusal with no replay.

3. `forwardOpenCodeRotating` needs **no** guard: a terminal 403 is not a usage
   limit, so `:152` already returns before `rotate()`.

**Non-goal.** We still cannot distinguish the other four causes. That needs the
dynamic identity derivation in §5, which this plan deliberately excludes.

## 2. Refusal retry cooldown (`internal/proxy/executor/opencode_retry.go`)

**Problem.** After a full-shape retry *still* answers 403, we retry again on the
very next request. Upstream's penalty is per-IP, so this is self-amplifying.

**Change.** One process-global timestamp — **not** a keyed map:

```go
var openCodeRetryCooldown = 30 * time.Second   // var: tests shrink it
var (
    openCodeRetryCooldownMu sync.Mutex
    openCodeRetryRefusedUntil time.Time
)
func openCodeRetryCoolingDown(now time.Time) bool   // lazy expiry on read
func noteOpenCodeRetryRefused(now time.Time)        // until = max(until, now+cooldown)
func resetOpenCodeRetryCooldownForTest()            // test seam
```

**Why global is exactly right, not an approximation:** the replay always leaves
from `forwardOpencodeRequestDirect` → `getOpencodeStealthClient(nil)` →
`opencodeProxyFrom(nil) == ""` → **unproxied**, i.e. one host IP per process.
The penalized entity *is* the process. Keying by `ConnectionID` or by proxy URL
would key the first attempt's egress rather than the replay's, letting N
connections burst N replays from the same flagged IP.

Bonus: no map, no pruning, no cap, no client-derived key — §4.G is satisfied
structurally rather than by a bound.

**Behaviour.** Suppresses only the *retry*; the first attempt of every request
always runs. Working egresses lose a free replay for ≤30 s.

**Wiring:** read the cooldown after the `StrictProxy` check and before the
`select` (`:111`); record it only when the *replay* is itself refused
(`:125` branch).

## 3. Carry the real `Retry-After` (`opencode_retry.go`, `providers.go`)

**Problem.** Three separate places throw away or overwrite the wait window:

| Site | Issue |
|---|---|
| `opencode_retry.go:75` `refusedResponseToError` | `resp.Header` is in hand but dropped |
| `providers.go:827` (chat) / `:747` (responses) | `UpstreamError` built without `Header` |
| `fallback.go:474-484` `opencodeClosureError` | **overwrites** with hardcoded 60/30 |

Note the plain-HTTP fallback path already keeps the header
(`internal/proxy/proxy.go:371`), so the two transports currently disagree.

**Changes:**

1. `refusedResponseToError` sets `Header: resp.Header`.
2. `providers.go:747` and `:827` set `Header: resp.Header`.
3. `classifyOpencodeFreeTierRefusal(provider, body)` → read the upstream header
   when present and prefer it over the hardcoded value; fall back to 60/30 when
   absent or unparseable. `opencodeClosureError` then passes it through instead
   of overwriting.
4. `/v1/responses` (`responses.go:246-283`) does not forward `Retry-After` at
   all (`chat.go:312-314` does). Add the same narrow pass-through — header only,
   never the framing headers.

**Decision (per your answer): keep `maxResetCooldown = 2h`** (`fallback.go:1685`)
as the safety cap. Upstream's real free-tier reset is ~21.5 h, so it will still
be clamped to 2 h and the egress re-probed ~10× early. That is accepted as a
follow-up, not part of this change — raising the cap is a cross-provider
policy decision.

## 4. Reasoning token floor + usage accounting

### 4a. Shared output-budget floor (`internal/proxy/executor/`)

**Problem.** `clampMuseSparkOutputBudget` (`providers.go:1541`) has exactly one
call site — the muse-spark **responses** branch (`providers.go:1658`). The free
**chat** lane (`ForwardOpencode`, `providers.go:681-842`) has **no clamp at all**
(verified: no `clamp`/`budget` in that range). Every free id in our capability
table is `Reasoning: true`, so a client sending `max_tokens: 100` gets empty
content with `finish_reason: "length"` — silently.

**Change.** One helper driven by `providers.GetCapabilitiesForModel(provider, model)`
(`capabilities.go:1073` — already resolves per-provider → canonical → pattern
rows, and is cached):

```
reasoning : min(max(requested, 1024) + 4096, MaxOutput)
plain     : min(max(requested, 512),  MaxOutput)
```

- Raise only — never lower a caller's value.
- Handle all three spellings (`max_tokens`, `max_output_tokens`,
  `max_completion_tokens`) via the existing `museSparkOutputBudgetFields`.
- Apply on: free `opencode` chat lane, free `opencode` responses lane, and
  `forwardOpencodeGoFree` (`providers.go:1715`).
- Replace the `museSparkMinOutputTokens = 512` constant with the generalised
  path so the same upstream does not have two different floors. Keep the
  constant's measurements in the comment — they are the evidence for 512.
- Reuse `outputBudgetOf` (`providers.go:1567`) for number decoding.

**Placement:** new file `internal/proxy/executor/output_budget.go` to keep
`providers.go` from growing (it is already >2000 LoC; AGENTS.md §4.D targets
≤300/fragment).

### 4b. `stream_options.include_usage` — **with a required second fix**

Setting the flag alone fixes **nothing**. `sseToOpenAIJSON`
(`internal/proxy/executor/codebuddy.go:433`) reads `chunk["usage"]` at **line
492, inside** the `if len(choices) == 0 { continue }` guard at `:474-477`. With
`include_usage: true`, OpenAI emits a final chunk with `choices: []` and
`usage: {...}` — that chunk is skipped and the usage discarded.

**Both changes are required:**

1. Set `stream_options: {"include_usage": true}` on the free opencode chat lane
   (mirroring `ForwardIflow`, `providers.go:165-175`). Never override a
   caller-supplied value.
2. In `sseToOpenAIJSON`, move the `usage` read **above** the `choices` guard so a
   usage-only trailing chunk is honoured.

**Impact today:** non-streaming free-lane callers get **no `usage` field at all**
(`codebuddy.go:567` only emits it when non-nil), so `usage.go:358` writes 0
tokens and `SettleTokenUsageFromContext` (`usage.go:330`) settles TPM against
nothing. There is no estimation fallback anywhere — confirmed, not assumed.

## 5. Explicitly out of scope

Recorded so the plan is not read as having missed them:

- **Dynamic identity derivation** (CLI version, UA, session recipe, tool schemas,
  endpoints, catalog) — the reference project's biggest win, but it adds a
  network dependency and a TypeScript source parser to a binary that has
  neither. Needs its own spike, with a TTL-bounded cache and fallback to today's
  constants per §4.G.
- **`run_code` quota filter.** Their measurement is strong, but our free lane
  *replaces* the tools array with the 12 genuine built-ins
  (`opencode_v2_fingerprint.go:92-129`), so `run_code` never travels as a
  declaration. Unmeasured on our shape — **measure against the live gate before
  porting.**
- **IPv6 / `ipv4first`.** The gateway refuses IPv6 egress; we have no equivalent.
  Transport-wide, not `opencode`-specific.
- **Proxy pool health/cooldown/`failover`.** `NextURL()`
  (`internal/db/proxyPools.go:155`) is a bare atomic counter and the `Strategy`
  column (`:23`) is stored but never read. Real gap, wrong scope for this change.
- **426 `UpgradeRequired` version adoption.** Pointless while our UA is the
  constant `opencode/latest/2.1.4/cli` — depends on §5's first item.

## Test-isolation hazard (must not be missed)

`TestForwardOpenCodeStopsAfterOneRetry` (`opencode_retry_test.go:83`) ends with a
refused replay, so it **records** the cooldown and leaks it into
`TestForwardOpenCode_ResponsePositionRefusalReplaysDirect`
(`opencode_rotation_test.go:192`), which then hard-fails. Follow the repo's
existing pattern — `resetFreePiCooldownsForTest`
(`free_pi_cooldown.go:67`):

```go
func resetOpenCodeCooldown(t *testing.T) {
    t.Helper()
    resetOpenCodeRetryCooldownForTest()
    t.Cleanup(resetOpenCodeRetryCooldownForTest)
}
```

Call it at the top of every test that can reach the replay path.

## Verification

Per-test (table-driven, `testing.T` only — AGENTS.md §5):

1. `TestIsOpenCodeTerminalRefusal` — the three abuse phrasings, the generic
   refusal, a near-miss (`"anti-abuse"` must **not** match), nil, empty body.
2. Terminal 403 → `directCalls == 0` **and** elapsed `< openCodeRetryDelay`
   (proves the sleep is skipped, not just the call).
3. Cooldown suppresses the *second* request's replay but not its first attempt;
   expiry restores it (shrink `openCodeRetryCooldown`).
4. Cooling down + 429 still rotates (rotation is not a retry).
5. `Retry-After` survives executor → handler: a 429 carrying
   `Retry-After: 3600` reaches the client as 3600, not the hardcoded 60.
6. Budget floor: table over reasoning/plain × {absent, 0, 50, 1024, 999999} ×
   `MaxOutput`, asserting raise-only and correct capping.
7. `sseToOpenAIJSON` with a trailing `choices: []` + `usage` chunk emits `usage`.

Then, in order:

```bash
rtk go test ./internal/proxy/executor/... -run 'OpenCode|OpenCodeRetry|Budget|SSE'
rtk go test ./internal/handlers/chat/... -run 'Opencode|RetryAfter'
rtk go test ./...
make vet-svelte          # only if web/ is touched — it is not, but cheap
make build
```

Integration (real router, fake upstream — AGENTS.md §5.D):

```bash

```

Regression assertions to keep green: `TestFreeTierRefusal_DoesNotCoolTheConnectionDown`,
`TestFreeTierRefusal_ReportsUnavailableNotForbidden`,

**Manual end-to-end** (needs a real free-tier call — no credential required):

# non-streaming, tiny budget: must NOT return empty content

  -H 'Content-Type: application/json' \

Assert: `content` non-empty, `finish_reason` not `"length"`, and `usage`
present with non-zero counts. Repeat twice and confirm the second call does not
replay on a refusal (check the `opencode` warn logs for a missing
"replaying" line inside the cooldown window).

## Risk notes

- The cooldown is process-global by design; a working egress loses one free
  replay for ≤30 s. Deliberate trade, stated in the code comment.
- The budget floor changes payload bytes for free-lane requests that previously
  sent a small `max_tokens`. Deterministic marshal
  (`marshalStable`) keeps the prefix cache stable, but the **first** request
  after this ships will re-prefix-cache once.
- `include_usage` adds a `stream_options` key to the free chat payload. The
  harness shaping must not interfere — verify with
  `TestInferenceGate_ShapedHarnessBodyAnswers200`.
- Do **not** widen `classifyOpencodeFreeTierRefusal`'s `"abuse"` match; it
  already over-triggers relative to the executor's narrower phrase list. If
  anything, narrow it — but that is a separate change.
